# 验收、测试与发布

需求编号 QA-*。本文件定义预期行为，当前没有应用测试通过的声明。合成数据用于确定性测试，真实数据需另做编辑审校。

## QA-01 标准环境与命令

实施时提供并固定：
- npm run validate:data：Schema/格式与跨引用校验正式 catalog。
- npm test：核心纯函数测试。
- npm run test:e2e：在本地静态服务上跑浏览器场景。
- npm run check：聚合本工作包需要的检查；CI 环境和本地命令一致。
- npm run dev：静态预览，不伪装成生产部署。

工具选择依据环境与官方文档，锁版本。若某命令需凭据/真实第三方服务，改成可重复的本地检查并说明差异。
浏览器覆盖：Chromium 桌面 1440×900、手机 390×844；最终人工验证 iPhone Safari。Safari 未检查标 pending，不用 Chromium 模拟冒充。
测试注入固定时钟；测试使用独立浏览器上下文和 storage fixture，不影响真实进度。

## QA-03 发布阻塞项

任一情况阻塞“验收通过”和生产发布：
- 默认或切回 safe 泄露敏感内容；分享 URL 自动开 full。
- 进度丢失/取消导入仍写入/未知版本被破坏。
- MVP 路线成员或顺序未核实，真实来源伪造。
- 主要按钮未实现、手机无法完成核心流程、Pages 子路径不可访问。
- 正式数据含合成 fixture；校验或关键行为检查失败。

非阻塞但必须明示：其余作品细年代未知、完整剧情待补充、Safari 实机待验、用户测试待做。不能把非阻塞未知值写成确定事实。

## QA-04 CI 与发布流程

1. 确认当前 Pages 是分支直发还是 workflow；应用开发只在工作分支进行，防止 main 推送意外发布。
2. PR 校验 schema/引用、单元测试、端到端关键场景；不在 public artifact 输出观看记录或凭据。
3. 保留现有托管方式；增加部署 workflow 前先查官方文档和实际配置，不擅自更改权限。
4. 审核数据清单、截图及 pending 事项；按当次授权合并/发布。
5. 发布后检查首页、目录、路线 hash、资源路径和非空计数；一次适当检查即可。
6. 回滚：恢复部署前 commit/产物，保留本机数据兼容。初版旧站没有进度逻辑，回滚不得主动删除新 progress 键。
7. docs/RELEASE_CHECKLIST.md 记录发布版本、恢复点、检查范围与失败处理。

性能：固定模拟环境记录字体/资源加载与布局稳定，不以一次实验室分数代表真实用户数据。目标数值沿用主计划；本轮不因图谱/海报加入大量未使用资源。
数据维护：事实变更提交来源、核实日期和变更说明，通过校验；自动来源监测只能生成审查建议，不自动发布剧情/档期。

## QA-05 用户反馈

邀请 5 位目标观众由项目拥有者安排：
- 第一次进入，找到合适路线。
- 查洛基资料，未意外剧透。
- 记录已看，刷新继续。
- 主动切 full 再回 safe，理解影响。
- 分享路线给新浏览器。

记录步骤、是否无需帮助完成、耗时和卡点；4/5 无帮助完成核心任务及多数 30 秒找到路线是初始目标，不是市场验证。
无参与者时如实记 pending；AI 模拟不算真人。后续图谱/新路线启动条件仍按主计划，不能以工程全部通过替代真实需求证据。
